## 2. My findings

### Finding 1

- **Where:** https://evstations.vercel.app, screen 1 (Nearest & Speeds), the current-charge percentage control at the top
- **What I did, what I saw:** I changed the current charge percentage at the top. The estimated charging speed shown for the listed stations changed with it.
- **Which heuristic:** 3. User and control freedom
- **Screen or system:** system, because to reduce complications
- **Severity, and why:** 1. Cosmetics only
- **The repair:** It should allow user to input exact number of charge % also

### Finding 2

- **Where:** https://evstations.vercel.app, screen 2 (Available Points), on first arrival
- **What I did, what I saw:** I switched from ‘screen 1’ to Available Points which is ‘Screen 2’. The postal code box was pre-filled with 038983 and showed results for that address, not the three nearest stations that screen 1 had just listed. Screen 2 is set to default location every time.
- **Which heuristic:** No. 1 Visibility
- **Screen or system:** System
- **Severity, and why:** 3, user can tell whats the issue at least, but might not know to navigate to screen 1 again to check slots in those nearest to them
- **The repair:** list the screen 1 options on screen 2

### Finding 3

- **Where:** https://evstations.vercel.app, screen 2 (Available Points), the postal code search box
- **What I did, what I saw:** I typed a valid postal code that is not the exact location of a known station, meaning a random postal code or my current location postcode. The search returned an error instead of the stations nearest to that postal code.
- **Which heuristic:** No. 1 Visibility of System Status and also No. 3 User Control and Freedom
- **Screen or system:** System, because the app is not set to showing nearest stations to the USERS search, only the exit matches
- **Severity, and why:** 3 to 4
- **The repair:** ask Google AI to add a code to search within a certain radius of users searched postal code

### Finding 4

- **Where:** https://evstations.vercel.app, moving from screen 1 (Nearest & Speeds) to screen 2 (Available Points)
- **What I did, what I saw:** I went to screen 2 directly to see slots for a station listed on screen 1. There was no way to reach it; the only route is pressing "Check slots" inside that station's card on screen 1.
- **Which heuristic:** 7. Flexibility and Efficiency of use
- **Screen or system:** SCreen, because system already has this info. But screen is not designed properly for the user
- **Severity, and why:** Sverity 3, on neilsen scale
- **The repair:** The user should be able to see nearest locations option on screen 2

### Finding 5

- **Where:** https://evstations.vercel.app, screen 2 (Available Points), the search box
- **What I did, what I saw:** I tried to search by a place name (e.g. a mall or MRT station). The box only accepts a six-digit postal code, so the search could not be made.
- **Which heuristic:** 6 Recognition Rather than Recall; 3 User Control and Freedom; 7 Flexibility and Efficiency of Use
- **Screen or system:** System, biggest failure in my app, not usable if the user needs to be so precise for the location of station, because they wouldn’t know and thats why they came to my app in the first place to search for the lcoation and not me making them search for it themselevs
- **Severity, and why:** 4, USER will run away
- **The repair:** it shouldn’t show error for user search but guide them to a nearest answer
